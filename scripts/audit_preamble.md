Branch `audit/bundled-library` (base `origin/main` 7e29a55). Target semantics: **Wolfram Language**.
Generated by `scripts/library_audit_report.py` from `mikoshilang.library.STATUS` and the differential
cases in `tests/library/`.

**Rule:** every exposed function either returns a correct result or raises a clear error
(`NotImplementedError` for unsupported or quarantined functionality, `ValueError` for invalid input). It must
never return a silently wrong answer. A function stays unevaluated only where Wolfram would also return it
unevaluated, for example symbolic arguments to a numeric routine.

## Method

* Every head the legacy library exposed (620 heads in `tests/library/inventory_heads.txt`, covering 617 loaded
  functions / 753 rules) was reimplemented or re-checked in an area module under `mikoshilang/library/`. The
  legacy `extended*.py` rule tables are no longer dispatched.
* **References:** SymPy, mpmath (to 30+ digits), SciPy, NumPy and NetworkX, plus values from the Wolfram
  documentation and CODATA 2018. Expected values are written down independently of the implementation.
  Several inputs are used per function, including edge cases: 0, negative, empty, singular, non-integer,
  disconnected and out-of-domain inputs.
* Each verified, fixed or promoted head has at least 3 cases. Each error or quarantined head has a case that
  asserts it raises. Each kernel head has at least one case. `tests/library/test_coverage.py` enforces all of
  this, and also checks that every one of the remaining quarantined names raises `NotImplementedError`.
* **Test matrix (local):** Python 3.9, 3.12 and 3.13 with `.[all,test]`, plus a minimal `pip install .`
  (3.12). CI runs the same matrix.

## Notable wrong answers found and fixed

| Area | Legacy behaviour | Now |
|---|---|---|
| elementary | `ArcTan[x, y]` argument order swapped | Wolfram order `ArcTan[x, y]` = arg(x + iy) |
| elementary | `Round` did not round half to even; `Max`/`Min` returned floats (`Max[1/2, 0.4]` → 0.5) | banker's rounding; the exact extremal element is returned |
| elementary | `Sign`, `Floor`, `Ceiling` returned floats | integers |
| numbertheory | `FactorInteger[1]` wrong; `ExtendedGCD` output order wrong; `JordanTotient`, `DiophantineSolve` always crashed | fixed, tested against SymPy |
| special | `Beta[1/2, 1/2]` stayed unevaluated; `InverseErf`/`BetaRegularized` not mapped | `Pi`; mapped to SymPy/mpmath |
| calculus | `TaylorSeries` off by one order; `InflectionPoints[x^4]` reported 0; `CriticalPoints` dropped tuple solutions; `DirectionalDerivative` not normalised; `Minimize` was a local float search; `RSolve` always crashed; `Sum[1/k]` did not diverge | Wolfram results |
| linalg | eigenvalue order and `Divergence` truncation | Wolfram ordering; raises on mismatched dimensions |
| optimisation | `LinearProgramming` used the wrong constraint sense | Wolfram `m.x >= b` |
| lists | `SubsetQ` argument order reversed; `Interleave` truncated silently | fixed |
| statistics | `Mode` returned only the first mode of multimodal data; `Quantile` used NumPy interpolation; `Kurtosis` used excess kurtosis | Wolfram definitions |
| statistics | distribution constructors accepted invalid parameters (`NormalDistribution[0, -1]`) | raise |
| transforms | Fourier transforms used SymPy's convention; SymPy also silently assumes k > 0, so `FourierTransform[1/(1+t^2), t, w]` gave `Sqrt[Pi/2] E^w` and `FourierTransform[Sin[t], t, w]` gave `0` | Wolfram convention, numerically verified at both signs of ω; distributional results raise |
| transforms | `FFT` rounded its output; `InverseFFT` dropped imaginary parts; `HilbertTransform` returned the analytic signal | exact or complex results |
| numerics | `GaussQuadrature` ignored n; `SimpsonsRule` silently changed odd n | real n-point Gauss–Legendre rule; odd n raises |
| logic | `Iff`/`Xnor` coerced symbols to `True`; the CNF/DNF/TruthTable family received undefined SymPy functions instead of Booleans; `BooleanMinimize[a \|\| !a]` was not `True` | stay unevaluated on symbols; exact Boolean algebra |
| graphs | `ChromaticNumber` was greedy (an upper bound only); `BetweennessCentrality` was normalised | exact backtracking; Wolfram unnormalised |
| applied | physical constants were rounded (`LightYear` = 9.461e15); 1-argument constant forms ignored their argument; legacy formulas used g = 9.81 and c = 3e8; `BohrRadius[n]` returned a0 | exact CODATA/SI values, `hbar`/`R`/`F`/`σ`/`Vm` derived exactly; extra arguments raise; `BohrRadius[n]` = n² a0 |
| applied | `CircleArea[-1]` = `Pi`; Carnot efficiency could be negative; finance rates ≤ −100% accepted | domain checks raise |
| plots | `Plot3D`, `ContourPlot`, `ParametricPlot`, `PolarPlot` were shadowed by inert descriptors; `Plot2D` drew an empty figure for bad input | real figures; errors raise |
| names | `Catalan`, `Trace`, `Degree` and `Root` had non-Wolfram meanings (`Catalan[n]` = Catalan number, and so on) | raise and point to `CatalanNumber`, `Tr`, `Exponent`, `Surd` |
| strings | legacy `Simplify` accepted strings and evaluated them | `sym()` rejects Python strings |
| knowledge | `EntitySearch` returned Wikidata's raw order (an engineer before Q42 for "Douglas Adams"); type hints were appended to the query, which found nothing; `EntityProperties`, `WikipediaSummary`, `Disambiguate` and `Entity` were never wired into the evaluator | relevance-ranked by sitelinks; P31/description filters; network-gated heads |

## Live-service tests (`-m live_service`)

Before the audit, 12 of 50 failed. **All 12 were caused by our code**, not by the services:

* the ranking and type-hint bugs (5 tests);
* the 4 unwired legacy heads (6 tests);
* one test that expected the unwired module's `"CC0 (Wikidata)"` licence label. The shipped evaluator uses
  `"CC0"` plus the entity URL as provenance, so the test was updated.

After the fixes: **50/50 pass** (run twice). These tests are excluded from default runs and CI
(`addopts = -m 'not live_service'`) because they depend on mutable remote data.
